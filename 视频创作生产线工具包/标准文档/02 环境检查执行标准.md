# 02 环境检查执行标准

## 一、用途与输入

确认同一工作区的共用制作环境能满足本期任务。输入为 01 已建立的本期工程、《选题确认记录》以及本期选用的工具和资源要求。需要确认视觉工具或资源时，按需读取本期采用的视觉方案。

**一个工作区共用一套制作环境。** 工作区为工具包同级的 `../视频创作/`。共用 Python 环境位于工作区的 `.venv/`，与各期作品目录并列。已有可用的系统工具和字体可按实际路径复用。

检查命令、依赖核对、macOS 与 Windows 的共用环境配置和缺项排查，按需读取[《视频制作环境配置》](视频制作环境配置.md)。

## 二、02.1 检查环境完整性

先核对工作区、本期工程和共用基础环境，再核对本期已经明确采用且需要提前就绪的工具和资源。局部任务用不到的项目记为「不适用」。

视觉方案、配音工具、专项依赖和共用素材如果由后续阶段确定，在 02 记为「待后续核对」，注明负责阶段。视觉方案及对应资源由 05–06 落实，配音工具和所需依赖在 06 使用前核对。此类事项不阻塞 02，也无须为通过 02 提前确定。

| 检查项 | 核对方法 |
| --- | --- |
| 工作区与本期工程 | 核对工作区、本期工程和阶段目录的实际路径，以及所需读写权限和可用空间。 |
| 共用 Python 环境 | 核对 `.venv/` 是否存在，使用该环境的解释器检查 Python 版本、本期直接依赖是否可导入，以及 `pip check` 的结果。 |
| 媒体工具 | 按本期制作方式核对 FFmpeg、FFprobe 等实际调用的路径和版本。按需查看编码器、字幕滤镜等能力列表。 |
| 字体与共用素材 | 核对本期使用的字体、配乐、参考图等资源的位置和可读性。 |
| 制作服务与查看工具 | 核对本期所需的配音、生图、资料和媒体查看工具入口及现有配置，记录已知的使用限制。 |

环境检查以实际路径、安装、导入、配置和能力列表为依据。实际配音、生图、导出和看听质量在对应制作阶段检查。02 无须为这些环节额外制作小样。

## 三、02.2 补齐并复查

1. **工作区尚无共用 Python 环境时**，使用可用且兼容本期工具的 Python，在工作区创建 `.venv/`，补齐本期需要的依赖。创建虚拟环境时使用该工作区下的目标路径，随后用新环境内的解释器核对实际结果。
2. **共用环境已存在时**，沿用已有环境。根据缺项修正调用路径、依赖或配置。发现既有环境异常时，先定位原因，在已有授权范围内处理。
3. 补齐后回到 02.1，只复查缺项及受影响的项目。确需新增授权、服务条件或用户操作，或执行依据不明确时，记录具体阻塞及需要补充的条件，暂停依赖该项的工作。

## 四、02.3 保存报告并交接

按[《环境检查报告编写规范》](../文档编写规范/环境检查报告编写规范.md)，将《环境检查报告》保存在本期工程的 `02 环境检查/`。报告记录实际复用或创建的环境、核对结果、缺项处理和复查结论。检查未能完成时保存已查结果和阻塞。

02 范围内的必需项齐备且报告可读，02 完成。「待后续核对」事项按报告交给相应阶段。报告结论为「就绪」后，当轮直接读取[《03 故事方案执行标准》](03%20故事方案执行标准.md)，开始执行 03.1。用户明确要求只测到 02 时，保存并核对报告后结束。
