# 视频制作环境配置

本文件供[《02 环境检查执行标准》](02%20环境检查执行标准.md)在检查和补齐环境时调用。它提供 macOS 和 Windows 的核对命令、共用环境创建方法和常见故障处理。检查范围、通过条件和报告位置由 02 执行标准确定。

## 一、定位本期实际使用的工具

以工具包同级的 `视频创作/` 为工作区。Python 虚拟环境位于工作区 `.venv/`，由同一工作区内的作品共用。命令在已确认的实际工作区中执行。终端能找到某个工具后，还要确认实际制作程序会调用同一路径。

| 项目 | 检查依据 |
| --- | --- |
| 系统与基础工具 | 记录操作系统、架构、可用 Python 解释器，以及 FFmpeg 和 FFprobe 的实际路径。已有工具满足要求时继续使用。 |
| Python 与依赖 | 用共用解释器查看版本和已安装包，对本期已明确需要的直接依赖逐项检查导入，并运行 `pip check` 检查已安装包的依赖关系。 |
| FFmpeg 与 FFprobe | 查看版本和本期所需能力。例如采用 H.264/AAC 输出或烧录字幕时，按实际分镜与导出方案核对相应编码器和滤镜。 |
| 字体与共用资源 | 核对字体文件、字体族名、实际使用的配乐或参考资料路径及可读性。采用的音视频素材按需核对来源与许可记录。 |
| 配音、生图和查看工具 | 核对已明确采用的工具入口、已有授权、配置状态和保存途径。凭据通过现有工具连接或受控配置提供。 |

可用下列命令识别本机工具。命令返回的路径和版本以实际执行结果为准。

**macOS**

```sh
sw_vers
uname -m
command -v python3
command -v ffmpeg
command -v ffprobe
```

**Windows PowerShell**

```powershell
[System.Runtime.InteropServices.RuntimeInformation]::OSDescription
[System.Runtime.InteropServices.RuntimeInformation]::OSArchitecture
Get-Command py, python, ffmpeg, ffprobe -ErrorAction SilentlyContinue
```

已知工具的实际路径时，可直接用该路径检查。Python 或 FFmpeg 确实缺失时，在已有授权范围内按本机系统、架构和所选工具的官方安装说明补装，再核对命令路径及版本。

## 二、创建或复用共用 Python 环境

工作区尚无 `.venv/` 时，用已核对兼容的解释器创建。以下示例中的 `python3` 或 `python` 须指向实际采用的解释器。已有环境时跳过创建命令，从环境内部的解释器开始核对。

**macOS**

```sh
python3 -m venv .venv
./.venv/bin/python --version
./.venv/bin/python -m pip list
./.venv/bin/python -m pip check
```

**Windows PowerShell**

```powershell
python -m venv .venv
& ".\.venv\Scripts\python.exe" --version
& ".\.venv\Scripts\python.exe" -m pip list
& ".\.venv\Scripts\python.exe" -m pip check
```

补依赖时，始终用共用解释器执行 `-m pip install`，并用同一解释器复查对应模块导入和 `-m pip check`。以已采用的程序或依赖清单为准，只安装缺项。旧流程常用依赖可按下表对照，实际采用哪些由本期工具决定。

| 用途 | 包名 | 导入名 |
| --- | --- | --- |
| 图卡、封面和图片处理 | Pillow | `PIL` |
| 图像或数值处理 | numpy | `numpy` |
| 音频切分和混音 | pydub | `pydub` |
| 使用 Edge 在线语音路线时 | edge-tts | `edge_tts` |
| 程序访问公开资料或下载文件 | requests | `requests` |

后续制作方式尚未选定时，相关专项依赖记录为「待后续核对」。如果已知直接依赖，核对其可导入性。空环境的 `pip check` 结果只说明已装包的依赖状态。

已有经过验证的依赖清单时按该清单恢复。首次搭建或有必要记录变更时，可用共用解释器的 `-m pip freeze` 保存版本快照。换机器时按目标系统和解释器重新建环境，复用适用的依赖清单、配置说明和资源。

## 三、媒体工具与资源怎么查

- **FFmpeg 和 FFprobe。** 分别运行 `ffmpeg -version` 和 `ffprobe -version`。按需运行 `ffmpeg -hide_banner -encoders` 和 `ffmpeg -hide_banner -filters` 查看能力。例：本期计划用 `libx264`、`aac` 和 `subtitles` 时，逐项核对是否可用。命令在终端可运行后，确认实际程序也能访问同一工具。
- **字体与资源。** 按采用的字体名或路径检查文件存在、可读，并区分字体文件路径与字幕配置中的字体族名。配乐、音效和参考资料优先查已采用的本地共用资源及索引，记录实际找到的文件和用途。资源有明确版本或指纹要求时，按该要求核对。
- **服务与播放器。** 记录本期实际采用的服务入口、连接配置状态和媒体查看能力。配音、生图和导出使用本期实际内容在对应阶段验证。02 记录能够执行的检查及限制。

## 四、常见问题的处理

| 现象 | 优先检查与复查 |
| --- | --- |
| 模块无法导入 | 查实际解释器、包名与导入名。在共用解释器中补缺失包，复查导入和依赖关系。 |
| FFmpeg 找不到 | 查安装位置与当前进程的 PATH。用已核对的绝对路径或修正配置，再运行版本命令。 |
| 缺编码器或字幕滤镜 | 核对当前 FFmpeg 构建与本期需要。调整到可用构建后重新查看能力列表。 |
| 中文显示异常 | 查字体文件、字体族名、文本编码及字幕配置。实际制作中复查受影响的字幕或图卡。 |
| 服务调用失败 | 从对应制作阶段的实际报错查版本、连接、授权或配置，修复后重试受影响的操作。 |
| 换机后路径失效 | 重新定位解释器、媒体工具、字体和资源。调用时正确处理中文、空格和本机路径。 |
| 工程写入失败 | 查实际输出位置、空间和权限。按已授权范围修复并复查。 |

补齐后只复查受影响项，将实际路径、版本、结果和仍需处理的事项写入本期 `02 环境检查/环境检查报告.md`。
