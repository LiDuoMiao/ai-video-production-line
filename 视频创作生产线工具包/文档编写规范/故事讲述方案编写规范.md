# 故事讲述方案编写规范

## 一、用途

03.1 用《选题确认记录》《资料初步调查报告》和题材讲述指南形成一份本期讲述思路，交给 03.2 制作故事框架。

## 二、内容与格式

在本期工程的 `03 故事方案/` 保存 `故事讲述方案.md`。按以下格式填写。

```markdown
# 故事讲述方案

- 本期选题：<已确认的选题>
- 题材：<已采用的题材>

## 切入点
<从哪个具体场景、事件、发现或问题开讲，观众从这里开始追踪什么>

## 讲述主线
<贯穿全篇的核心问题，以及用什么经过或变化推动讲述>

## 展开顺序
<用几句话说明开头之后先讲什么、接着讲什么>

## 结尾回应
<结尾回应哪个问题，初查资料目前能支撑讲到什么程度>
```

## 三、各部分怎么写

| 部分 | 填写要求 |
| --- | --- |
| 切入点 | 具体到一个可辨认的事件或问题，并写明为什么由此进入本期故事。 |
| 讲述主线 | 只保留能贯穿本期的核心追踪问题。各部分应能沿它推进。 |
| 展开顺序 | 按观众接收信息的顺序写出主要推进方向。需要回溯时，交代在哪儿回去、回溯解决什么。 |
| 结尾回应 | 对应开头的疑问。尚无依据的解释或结果留待核对。 |

## 四、自查与交接

核对方案和用户确认的对象一致，切入、主线、顺序与结尾能相互对应。写到 03.2 能据此分段即可。后续补查改变核心讲法时，更新受影响的方案内容。
