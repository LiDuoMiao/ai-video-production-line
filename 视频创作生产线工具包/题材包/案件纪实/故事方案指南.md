# 案件纪实故事方案指南

## 一、用途

供 **03.1 生成故事讲述方案**和 **03.2 制作故事框架**使用。以用户确认的案件及初查材料为依据，确定从哪里讲起、观众要追踪什么，以及每段怎样推进。两项产物的格式按[《故事讲述方案编写规范》](../../文档编写规范/故事讲述方案编写规范.md)和[《故事框架编写规范》](../../文档编写规范/故事框架编写规范.md)执行。

## 二、03.1 生成故事讲述方案

1. **从已有资料找切入点。** 可以从首次发现、两条记录对不上、一次调查转向或一个待解释的结果开讲。选择一个既有资料支撑、又能自然引出核心问题的节点。关键细节只有转述或仍未核实时，写明需要查证的部分。
2. **确定一个追踪问题。** 把「介绍这起案件」具体化，例如「为什么原来的判断需要修正」「哪条资料把调查引向了另一方向」。只纳入推动或解释主线的背景。
3. **安排观众接收信息的顺序。** 根据案件选用顺叙、从转折切入后回溯等方式。用时间、地点或事件说明回到了哪里。讲到某个阶段时，交代当时已知的事实、仍未解答的问题及下一步为何发生。
4. **确定结尾要回应什么。** 说明可以讲到的调查或裁判结果，以及仍待核实的关键问题。初查资料支持到哪里，方案就先写到哪里。后续核对发现核心问题无法支撑时，调整切入或主线。

案件的悬念来自真实存在的疑问、信息差和判断变化。线索出现时所处的调查阶段、不同说法的归属和结论成立的条件，都应保留在讲述设计中。

## 三、03.2 制作故事框架

1. **按观众的理解顺序分段。** 用《故事讲述方案》的主线安排各段。每段推进一件可辨认的事情，例如建立起初的认识、出现新信息、核查一个疑点，或交代已知结果。
2. **写清各段怎么接。** 说明本段承接哪个问题、发生了什么变化、下一段为什么要讲。使用回溯或提前展示结果时，在框架中标明实际时点和观看顺序。
3. **逐段列出需要的依据。** 写到可以定向查找的程度。比如要讲「一条新记录改变了原判断」，需要知道原判断基于什么、新记录何时出现，以及来源是否说明它如何影响后续判断。
4. **把讲述意图和待核实事实区分开。** 现有资料只支持两件事先后发生时，将两者是否有因果关系列为待核实问题。关键人物身份、行动、证据、判断和结果沿用来源实际能支持的说法。

框架完成后，交 03.3 对照已有资料逐段核对。资料查不到时，按 03 执行标准调整受影响的讲法，再核对相关段落。

## 四、简短示例

以下为虚构示例，用于说明从讲述方案到故事框架的转换。

**讲述方案。** 从两份时间记录对不上切入。主线追踪「差异究竟意味着什么」。先让观众看见矛盾，再回溯原来的时间线如何形成，最后交代核查确认了什么。

| 段落 | 讲什么、怎样接 | 需要的依据 |
| --- | --- | --- |
| 01 两份记录 | 先交代两份记录出现差异，引出原时间线的来历。 | 两份记录分别记了什么、对应的是不是同一事项。 |
| 02 原来的时间线 | 回溯原先怎样判断，说明哪一点需要核实。 | 两份记录的时间、出处，以及来源如何描述原先的判断。 |
| 03 核查结果 | 说明能确认什么、还不能确认什么，回应开头的差异。 | 核查结果，以及是否有资料明确说明差异影响了后续判断。 |
